# Ideas y misiones para colaboradores

¡Bienvenido! Este documento reúne oportunidades de colaboración para BUNKKER E.C.O.S. Son **propuestas iniciales**, no promesas del roadmap ni tareas aprobadas. Abre un Issue para confirmar prioridad, alcance y que nadie más esté trabajando en la misión antes de comenzar.

## Cómo proponer una misión

Describe el problema, a quién afecta, el resultado esperado, criterios de aceptación y cómo probarlo. Evita incluir credenciales o datos reales. Las ideas también se pueden conversar en [GitHub Discussions](https://github.com/ataca3000/bunnkker-e.c.o.s-baas/discussions).

## Misiones para empezar

### Documentación y experiencia de desarrollo

- [ ] **Revisar el inicio rápido:** probar la instalación desde cero y reportar pasos confusos o faltantes, sin publicar secretos.
- [ ] **Mapa de módulos:** documentar una parte concreta de la aplicación con enlaces a sus carpetas y rutas relevantes.
- [ ] **Glosario del producto:** proponer definiciones breves para roles, estados de pedidos y términos de inventario usados en la interfaz.

### Calidad y pruebas

- [ ] **Cobertura de una función existente:** identificar una función de negocio y proponer pruebas Vitest para sus casos exitosos y límites.
- [ ] **Lista de verificación manual:** documentar cómo validar un flujo en ambiente local sin usar datos de clientes reales.
- [ ] **Accesibilidad de una pantalla:** revisar teclado, etiquetas y contraste en una pantalla acordada, y reportar hallazgos con pasos reproducibles.

### Producto y operación

- [ ] **Flujo de caja:** proponer casos de prueba para apertura, cobro y cierre, sin alterar reglas financieras hasta acordar el alcance.
- [ ] **Inventario y movimientos:** documentar escenarios de alta, ajuste y merma, incluyendo el resultado esperado para auditoría.
- [ ] **Catálogo virtual:** revisar una mejora pequeña de claridad o navegación móvil y presentar capturas o una propuesta antes de implementar.

### Comunidad

- [ ] **Plantillas de Issues:** proponer campos para que los reportes incluyan versión, pasos reproducibles y resultado esperado, sin datos privados.
- [ ] **Guía para nuevos colaboradores:** simplificar un paso del entorno de desarrollo y validarlo con alguien que no conozca el repositorio.

## Para reportar una idea o error

Abre un [Issue](https://github.com/ataca3000/bunnkker-e.c.o.s-baas/issues/new) con título claro y contexto suficiente. Para errores, incluye pasos para reproducir, resultado esperado/obtenido y entorno. Para ideas, explica la necesidad antes de proponer una solución concreta.

## Cuándo una misión está lista

La misión se considera lista cuando su alcance está confirmado en un Issue, los criterios de aceptación son verificables, los cambios respetan las guías de [CONTRIBUTING.md](../CONTRIBUTING.md) y el PR describe las pruebas realizadas.
